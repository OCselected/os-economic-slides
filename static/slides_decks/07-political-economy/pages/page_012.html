从 Emacs 的闭源转向到 Xz 后门危机——一份关于开源协作脆弱性的编年清单，映射制度环境下共同体所承受的外部压力与内部裂变。
01
Emacs 被闭源 GNU Emacs 早期版本在商业利益驱动下短暂转向闭源，标志着自由软件运动面临的第一个重大制度性危机。
COMMUNITY
02
Kerberos 被微软所窃取 MIT 的 Kerberos 认证协议被微软直接吸纳进 Windows 域控体系，核心技术被商业帝国私有化利用。
CORPORATE
03
OpenSSL Heartbleed 事件 2014 年，OpenSSL 致命漏洞曝光，全球数十亿设备受影响，暴露了关键基础设施维护者的资金与人力困境。
INFRASTRUCTURE
04
2001 微软从媒体开始攻击开源许可 微软发动「拥抱、延伸、熄灭」战略，通过媒体话语体系系统性污名化 GPL 与开源运动。
DISCOURSE
05
Xz 后门事件 2024 年，广泛部署的 Xz Utils 被植入供应链后门，险些攻陷 Linux 系统，揭示单人维护关键包的系统性风险。
SUPPLY CHAIN
06
C4 IDE 套壳 VS Code，引发热议 中国厂商基于 VS Code 开源代码套壳发布国产 IDE，模糊「基于」与「抄袭」的制度边界，引发开源社区广泛讨论。
